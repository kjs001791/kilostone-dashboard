## 기존 규칙은 그대로 두고 새 규칙 하나만 더했다

처음에 "자동 수정은 주행거리만" 을 기존 규칙 삭제로 읽어 만들었다가 주 세션 정정을 받고 되돌렸습니다. 지금 편집기(`policy="combined"`)는 2차까지의 규칙(이상 날짜 고정, 전날 값 복사, 오타 역산, 최소 칸 수정, 같은 날 병합)을 그대로 두고, 새 규칙 하나를 더합니다.

- 새 규칙: 누적거리 사슬이 덮지 않는 행(그 줄에 누적거리가 없고 사슬 구간에도 안 든 행)에서, 연비 × 연료와 속도 × 시간이 같은 거리를 가리키고(두 값의 차이가 두 허용 오차의 합 이내), 적힌 주행거리의 오타 후보(자리 바꿈, 자리 누락·추가, 옆 키, 다른 숫자) 중 두 계산에 모두 맞는 것이 하나뿐이면 주행거리를 고칩니다. 주행거리 외 칸(연비, 연료, 속도, 시간)은 이 경로에서 안 고칩니다.
- 안 고치고 경고만 남기는 경우를 행 판정으로 센 값: `relations_disagree`(두 계산이 서로 다른 값을 가리킴), `several_candidates`, `no_candidate`, `one_relation_only`, `relation_not_valid`(그 차량에서 관계가 75% 미만 성립), `off_unit_grid`.
- 2차 편집기는 `policy="legacy"` 로 남겨 전후 채점에 씁니다.

## 차량 구분은 제목 글자 우선으로, 새 양식은 격리 없이 적재하도록 바꿨다

1. `parse_driving.py` 차량 구분: 시트 제목 글자(헤더 위 15행 안에서 "운행" 이나 알려진 모델 낱말이 든 첫 글자 칸)를 먼저 봅니다. 새 칸 `vehicle_title`(제목 원문, data/ 파일에만), `vehicle_model_key`(정규화된 모델 낱말, 없으면 빈칸), `vehicle_id`(vehicles.toml 이 채워질 때만), `vehicle_source`(title, title_unknown_model, header_text, structure, none), `extra`. `vehicle` 칸은 편집기가 묶는 키입니다: 차량 ID, 없으면 모델 낱말, 제목은 있는데 모델 낱말이 없으면 제목 해시, 제목이 없을 때만 칸 모양 짐작. "대우" 단독은 모델 낱말로 안 칩니다(새 대우 차를 프리마로 오인하지 않기 위해).
2. 새 양식 대비: 날짜 칸과 측정 칸이 하나라도 있고, 제목에 "운행" 또는 알려진 모델 낱말이 있거나 주행거리 칸이 있으면 세 양식이 아니어도 적재합니다. 모르는 칸은 `extra` 에 "원래 머리글 → 값" JSON 으로 보존합니다. 근거 없는 시트(매출 모양)는 격리합니다.
3. `pipeline/vehicles.toml`: 차량 ID, 모델명, 연식, 운행 시작, 운행 끝, 제목 낱말 칸만 있고 값은 빈 틀입니다. 채우면 파서가 날짜와 제목으로 맞는 항목이 정확히 하나일 때만 `vehicle_id` 를 붙입니다. 모델명과 연식만 있으면 `<모델 키>-<연식>` 으로 ID 를 만듭니다.
4. `edit_driving.py`: 차종 이름으로 갈리는 곳은 없었고, 검사는 이미 칸 유무로 갈렸습니다. 이번에 이를 명시했습니다. 차량마다 쓸 수 있는 검사를 칸에서 읽어 `info["checks"]` 에 남깁니다. 위 새 규칙을 더했고 `evaluate.py` 의 MAN 전용 채점을 "누적거리가 없는 행" 기준으로 바꿨습니다(`make_dummy.inject_man_distance` 도 같음).

## 막힌 곳 여섯 가지가 남아 있다

1. MAN 제목에 알려진 모델 낱말이 없어 해시 키로 묶였습니다. 차량 ID 는 vehicles.toml 에 채우거나 MAN 제목 낱말을 알려 주시면 붙습니다. 차량 목록은 아직 못 받았습니다.
2. 같은 날 같은 차 충돌(미해결 6묶음, 중복 충돌 12행)은 차량 ID 가 있어야 진짜 다른 차인지 가릴 수 있습니다.
3. Daewoo 와 Scania 는 누적거리 사슬이 덮어서 새 규칙 대상이 아닙니다. 새 규칙은 이번 표에서 MAN 양식 행에만 적용되었습니다.
4. 최소 칸 수정 켬/끔(위 실제 원본 절).
5. 2차의 "소프트 규칙 자동 수정 허용 여부" 질문은 이번 새 규칙이 누적거리 없는 행에서 답했습니다. 사슬이 덮는 행에서는 여전히 경고만 합니다. 주 세션 정정에 따라 사용자 확인이 오면 다시 알려야 하는 부분입니다.
6. 같은 날 병합(빈칸 채움)은 2차 규칙이라 그대로 둡니다. 연비, 연료 같은 다른 칸의 빈칸도 채우므로 "다른 칸은 경고만" 과 부딪히는지 사용자 확인이 필요합니다.

## 한계는 더미 점수와 실제 7칸 수정이 검증되지 않은 것이다

- 더미 점수는 내가 가정한 오류 분포에서 나온 값이다. 실제 오타 분포와 다를 수 있다.
- 새 규칙의 판정 기준(두 계산의 허용 오차, 75% 이상 성립하는 차량만 사용)은 더미와 실제 MAN 양식 행에서 확인했다. 실제에서 새 규칙이 고친 7칸이 맞는지는 값을 열어 보지 않아 모른다. 확인 목록(`data/review/driving_review_list.csv`)에서 사용자가 볼 수 있다.
- 연비나 연료 칸이 틀린 행에서 주행거리가 맞는 경우, 새 규칙이 멀쩡한 주행거리를 잘못 고칠 수 있다. 더미에는 그런 오류가 없어 이 위험은 측정하지 못했다.
- 시험용 점수는 한 번 본 숫자이다. 이 시드로는 다시 채점할 수 없다.
- 제목 해시 키는 같은 제목 글자를 가진 시트를 한 차로 묶는다. 서로 다른 차가 같은 제목을 쓰면 한 차로 합쳐진다.

## 사용자가 MAN 제목 낱말과 두 설정을 정해 주기를 권고한다

1. MAN 양식 시트 제목에 쓰인 낱말 하나를 알려 주거나 차량 목록을 `pipeline/vehicles.toml` 에 채운다. 그러면 `vehicle_id` 가 붙고 2020년 같은 날 중복이 차량별로 갈린다.
2. 최소 칸 수정을 켤지 정한다. 실제 미해결 행이 46행인지 13행인지가 갈린다.
3. 같은 날 병합이 연비·연료 등 다른 칸의 빈칸을 채우는 것을 허용할지 정한다.
4. 새 규칙이 고친 7칸을 확인 목록에서 본다.

## 후속: 스카니아는 한 시기뿐이고 시기 분할을 갖췄다

주 세션 후속 지시(차량 테이블 칸 변경, 스카니아 두 대)를 반영했다. 값, 날짜, 좌표는 찍지 않았고 건수만 냈다.

### 스카니아 행은 두 시기로 갈리지 않았다

운행 순서가 스카니아, MAN, 대우, 스카니아라면 날짜 순 브랜드 열에 스카니아가 두 번 나와야 한다. 적재된 3,242행에서는 그렇지 않았다.

| 확인 | 건수 |
|---|---|
| 날짜 순 브랜드 열(5행 이상 연속 구간) | MAN 1,072행, 대우 1,657행, 스카니아 511행의 세 구간 |
| 스카니아가 다른 브랜드 구간을 사이에 두고 끊기는 자리 | 1곳. 앞쪽은 1행, 뒤쪽은 511행. 간격 333일, 그 사이 다른 브랜드 250행 |
| 누적거리 수준이 바뀌는 자리(역행 1,000km 초과 또는 하루 1,000km 초과 증가) | 4곳이 나왔으나 두 쌍이 각각 이웃해 있어(앞뒤 72/139행과 73/138행, 144/67행과 145/66행) 수준 변화가 아니라 튀는 값 2개로 읽힘 |
| 스카니아 행 중 대우 마지막 날짜보다 앞선 행 | 1행 |

출처: `data/parsed/driving.csv` 를 스크립트로 집계한 건수(내가 열지 않음). 대우 행 1,658 중 1행은 1902년으로 잘못 적힌 날짜 행이라 이 집계에서 뺐다.

해석: 적재된 스카니아는 사실상 한 대(2023~2026 구간, 511행)이고, 첫 번째 스카니아(MAN 이전)는 적재 행에 없다. 격리된 시트 257개나 파일에 없는 기간에 있을 수 있으나 확인하지 못했다. 앞쪽 1행은 별개 시기라고 보기엔 너무 짧아 날짜 오기 후보로 본다. 첫 스카니아가 어느 파일에 있는지 사용자 확인이 필요하다.

### 차량 ID 는 브랜드와 기간으로 붙고 빈 틀이면 임시 키로 나뉜다

- `pipeline/vehicles.toml` 칸: `vehicle_id`(V01 같은 뜻 없는 번호), `brand`, `model`, `model_year`, `service_start`, `service_end`, `title_words`. 값은 비어 있다. 이전의 `model_name` 칸과 ID 자동 생성은 없앴다.
- 채워지면: 제목에서 찾은 브랜드(또는 제목 낱말, 브랜드 글자)가 맞고 날짜가 운행 기간에 드는 항목이 정확히 하나일 때만 `vehicle_id` 를 붙이고 `vehicle`(편집기가 묶는 키)을 그 ID 로 바꾼다. 스카니아 두 대는 운행 기간으로 갈린다. 기간 밖 날짜나 두 항목에 걸친 행은 ID 없이 남는다.
- 비어 있으면: `split_periods` 가 한 브랜드 키를 `Scania-1`, `Scania-2` 로 나눈다. 같은 키 행이 30일 넘게 끊기고 그 사이 다른 키 행이 있는 자리에서 끊되, 양쪽이 각각 20행 이상일 때만 끊는다(짧은 구간은 날짜 오기 같은 떠돌이 행으로 보고 이웃에 합친다). 누적거리 사슬, 소프트 관계, 같은 날 병합은 모두 `vehicle` 키 단위로 돌기 때문에 차 단위가 된다.
- 지금 데이터에서는 나뉘는 키가 없다(스카니아의 앞쪽 1행이 20행 미만이라 합쳐짐). 그래서 편집 결과는 3차 본문과 같다.
- 시험: `tests/test_driving_vehicle.py` 에 브랜드 + 기간 매칭(스카니아 두 대와 기간 밖 날짜), 임시 시기 분할(끊김, 사이에 다른 차가 없는 간격, 떠돌이 행)을 더했다.

### 다시 돌려도 대사 불일치 0이고 시험 22개가 통과했다

| 조건 | 결과 |
|---|---|
| 시트별 대사 불일치 0 | 통과 (0 / 시트 390). 적재 3,242행 그대로 |
| pytest | 통과, `tests` 전체 22개 중 22개 (다른 작업자의 시험 포함) |
| 값, 좌표, 제목 원문 0 | 통과로 봄. 집계 스크립트와 실행 콘솔에 건수만 찍음 |
| 실제 편집 결과 | 자동 수정 36칸, 미해결 46행으로 3차 본문과 같음 |

출처: `pipeline/parse_driving.py`, `pipeline/run_real.py` 실행 콘솔과 pytest.

한계: 시기 분할은 "다른 차가 사이에 달렸다" 는 날짜 정황에만 기댄 임시 키다. 같은 브랜드 두 대가 같은 기간에 번갈아 달렸다면 갈리지 않는다. 확정은 vehicles.toml 을 채워야 한다.

사용자에게 권고: 첫 번째 스카니아의 기간과 그 시트가 어느 파일(또는 격리 시트)에 있는지 알려 주고, vehicles.toml 을 V01~V04 로 채우면 된다.
