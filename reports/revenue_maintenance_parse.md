# 매출과 정비는 표준 파일이 생겼고 매출 행의 55%는 격리됐다

파서는 `pipeline/parse_revenue.py` 입니다. 허용 목록과 도우미는 `pipeline/revenue_common.py`, 최신 비교는 `pipeline/compare_latest.py`, 시험은 `tests/test_parse_revenue.py` 에 있습니다. 이 문서에는 건수와 허용 목록 낱말만 있습니다. 값, 셀 좌표, 시트 이름, 허용 목록 밖 글자는 없습니다.

## 사용자가 해야 할 일은 칸 의미 알려 주기와 날짜 가정 확인이다

- 격리된 두 갈래 표의 칸 의미를 구조 수준으로 알려 준다. 대표 시트 하나씩에서 어느 칸이 날짜, 수량, 금액인지만 말하면 된다. 값은 필요 없다
- 파일 이름 기준으로 채운 날짜 1,827칸이 맞는지 확인한다. 한 파일 안의 모든 시트가 파일 이름의 월이라는 가정을 썼다

## 칸 이름은 허용 목록을 통과한 낱말만 글자로 남겼다

허용 목록은 `revenue_common.py` 의 `RULES` 입니다. 머리글이 허용 낱말과 정확히 같을 때만 글자로 찍습니다. 숫자, 괄호, 단위는 빼고 비교합니다. 나머지는 `<other:N자>` 로 찍습니다.

출처: 실행 출력의 표준 칸별 시트 수.

| 폴더 | 표준 칸에 매핑된 시트 수 |
|---|---|
| revenue | date 183, destination 209, origin 209, unit_price 220, vehicle 208, weight_ton 149, supply_amount 133, vat 133, total_amount 133, amount 28, note 27, client 19, quantity 12 |
| maintenance | item 5, note 3, cost 2, shop 2, odometer_km 2, date 1, vehicle 1, unit_price 1 |

표준에 못 넣은 칸의 머리글은 글자 수로만 보입니다. 매출은 12가지 글자 수(2~13자), 정비는 9가지입니다. 그 값은 전부 `extra` 에 들어갔습니다.

## 표준 칸 매핑은 아래 낱말로 정했다

출처: `revenue_common.py` 의 `REVENUE_RULES`, `MAINTENANCE_RULES`.

| 표준 칸 | 인식하는 낱말 |
|---|---|
| date | 날짜, 일자, 일시, 년월일 (정비는 정비일 추가) |
| client | 거래처명, 거래처, 업체명, 업체, 상호 |
| origin, destination | 상차지, 출발지, 상차 / 하차지, 도착지, 하차, 납품처 |
| item | 품목, 품명, 상품, 제품 (정비는 정비내용, 정비항목, 수리내용, 항목, 부품, 내용, 정비) |
| quantity, weight_ton, trips | 수량, 물량 / 톤수, 톤, 중량 / 운행횟수, 횟수, 회수, 건수 |
| unit_price | 단가, 운임단가 |
| amount, supply_amount, vat, total_amount | 금액, 운임, 매출액, 매출, 청구액, 운송료 / 공급가액, 공급가 / 부가세, 세액 / 합계금액, 합계, 총액 |
| vehicle, note | 차량번호, 차량, 차번, 차종, 호차 / 비고, 적요, 메모 |
| 정비 전용 | cost(수리비, 정비비, 부품비, 공임, 비용, 금액), shop(정비업체, 정비소, 공업사), odometer_km(주행거리, 누적거리, 키로수, km) |

출력 칸은 `source_folder, source_file_no, source_sheet_no, source_row_no, file_hash, table_kind, 표준 칸들, date_basis, extra` 입니다.

- `table_kind` 는 시트에서 표준 칸에 매핑된 칸 이름을 이은 구조 표지다
- `extra` 는 원래 머리글에서 값으로 가는 JSON 이다
- 거래처 이름이 윗단 머리글인 칸은 표준 칸에 넣지 않고 합친 머리글 그대로 `extra` 에 둔다
- 표준 칸이 숫자나 날짜인데 값이 글자면 `extra` 로 옮기고 표준 칸을 비운다. 매출에서 날짜 344칸, weight_ton 57칸, supply_amount 57칸, vat 57칸, total_amount 4칸, unit_price 5칸이다
- 정비 사진은 `maintenance_photos.csv` 에 시트별 행과 열만 두고, 대사 파일의 `photos` 칸에 개수를 둔다

## 한계와 가정은 격리된 두 갈래 표, 병합 셀, 날짜 추정이다

## 후속: 매출 격리 행은 11,582에서 77로 줄었다

위쪽 절의 격리, 적재, 비교 수치는 이 절이 대체합니다. 66시트 갈래와 72시트 갈래는 같은 양식(가로형)이었고, 합계표는 아니었습니다. 정비는 그대로입니다(격리 5시트, 240행).

### 1. 병합 셀 채우기는 1칸이었다

출처: `pipeline/parse_revenue.py` 실행 출력의 `merged-cell fill` 줄과 병합 범위 구조 집계.

| 항목 | 건수 |
|---|---|
| 채운 칸 | 1칸 (1시트) |
| 정상 시트 234개의 병합 범위 | 2,722 |
| 세로 병합 (전체 84, 데이터 행 영역 안 76, 그중 채울 표준 칸 위 17) | 84 |

### 2. 격리 141시트 중 138시트가 가로형이라 풀어 적재했다

판정 기준은 세 가지입니다.

1. 첫 글자 칸이 거래처나 일자 계열 낱말이고 그 오른쪽에 허용 목록에 없는 글자 칸이 2개 이상인 행이 위쪽 40행 안에 있다. 같은 행의 숫자 칸은 옆 블록으로 보고 라벨에서 뺀다
2. 허용 목록에 없는 라벨의 80% 이상이 그 칸(병합이면 병합 폭) 아래에 숫자를 가진다
3. 데이터 행의 20% 이상이 첫 글자 칸 자리에 날짜나 "N일" 을 가진다

풀어낸 결과는 다음과 같습니다. 머리글 글자는 `revenue.csv` 의 `extra` 에만 있습니다.

### 3. 66시트 갈래는 합계표가 아니라서 이름을 바꾸지 않았다

66시트 갈래(첫 행에 합계 라벨)와 72시트 갈래는 서로 다른 표가 아니라 같은 양식이었습니다. 제목 줄에 합계 라벨이 있고 3행에 가로형 머리글이 있는 시트라서, 위 2의 가로형 138시트에 모두 들어갔습니다.

합계표 가설은 따로 셌습니다. 같은 파일 안 정상 시트의 숫자 칸 합계와 이 갈래의 숫자(절대값 100 이상)를 비교했습니다.

출처: 실행 출력의 `summary candidates` 줄과 일회성 진단 집계.

| 비교 | 일치 / 전체 |
|---|---|
| 가로형 풀기 전, 머리글 없는 71시트의 숫자가 정상 시트의 칸 합계와 같은 개수 | 0 / 8,906 (0%) |
| 같은 숫자가 정상, 가로형, 운행기록 시트의 칸 합계나 누적 합과 같은 개수(허용 오차 1) | 44 / 8,906 (0.5%) |
| 지금 남은 3시트(격리) | 0 / 67 |

일치율이 0%라서 합계표(중복 정보)로 확인된 시트는 0개이고, `table_kind=summary` 와 사유 '합계표(중복 정보)' 는 코드와 시험만 있고 실제 데이터에는 적용되지 않았습니다. 남은 3시트의 사유는 '머리글 없음' 입니다.
